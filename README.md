# AI Sana — MVP решения кейса HackAlem

Автономный веб-MVP для AI Sana: бизнес превращает свободное описание потребности в редактируемую карточку, получает прозрачный рейтинг готовности, публикует задачу в общем каталоге, а студенческие команды отправляют предложения. Финальное решение всегда принимает представитель бизнеса вручную.

## Быстрый запуск

Проект не требует npm, базы данных или внешнего API.

Откройте http://localhost:8000.

## Что реализовано

- Свободный ввод черновика и отрасли.
- Название компании заказчика сохраняется в карточке и используется как контекст для AI-анализа.
- Локальная AI-заглушка: анализирует только введённый текст, формирует минимум 3 уместных вопроса, показывает missing fields, prompt, формат input/output и безопасный fallback.
- Редактируемая карточка: название, контекст и потребность, пользователи, данные, ожидаемый результат, критерии успеха, ограничения, контакт и формат взаимодействия.
- Рейтинг 0–100 с расшифровкой баллов и пересчётом после каждого изменения.
- Уровни: 0–39 черновик, 40–69 рабочая, 70–89 готовая, 90–100 приоритетная.
- Публикация только после ручного подтверждения. Низкий рейтинг не скрывает задачу.
- Общий каталог со свободным поиском, фильтром готовности и сортировкой по рейтингу.
- Неограниченные отклики: идея, план/срок и ссылка на прототип.
- Ручные действия бизнеса «Принять» / «Отклонить».
- Режимы «Бизнес» и «Студент», разделы откликов, команд и демонстрации.
- AI-агент декомпозиции: из опубликованной задачи заказчика создаёт редактируемую зависимую карточку с целью, входными данными, артефактом, критериями приёмки и ограничениями.
- AI-помощь для каталога и откликов: рекомендации команд с объяснением совпадения, проверка полноты предложения, сравнение откликов и журнал фактического прогресса после принятия команды.
- Встроенный минимальный набор данных: 5 черновиков, 5 карточек, 5 профилей команд, 5 откликов.
- Данные сохраняются в localStorage, регистрация, чат, уведомления, календарь и сложные роли отсутствуют намеренно.

## Формула рейтинга

Баллы начисляются только если поле заполнено содержательным текстом не менее 8 символов. Максимум 100:

| Показатель | Вес |
|---|---:|
| Контекст и потребность | 20 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и формат взаимодействия | 10 |

## AI-правила

AI не добавляет факты, которых не сообщал пользователь. Сформированный текст можно редактировать, а публикация требует подтверждения человека. AI не ограничивает общий каталог, не назначает исполнителей и не использует персональные или чувствительные признаки участников. Внешний API в MVP не нужен: deterministic fallback позволяет показать рабочую логику на защите.

## AI-агент зависимых заданий

В каталоге у каждой опубликованной задачи есть действие «Создать зависимое». Агент получает только поля родительской карточки и выбранные пользователем роль и фокус, после чего формирует черновик подзадачи. Черновик можно отредактировать и сохранить в разделе «Зависимые задания»; он не публикуется автоматически и не назначает исполнителя.

Основная задача AI-агента: принять название компании и свободное описание потребности, аккуратно разложить его по полям карточки, показать недостающие сведения и задать уточняющие вопросы. Агент не должен придумывать факты, поэтому реальные API-ключи для базового сценария не требуются. При подключении внешней модели ключ следует хранить только на backend, а не в `index.html` или `app.js`.

Для студентов агент объясняет совпадение команды с задачей, но не выбирает исполнителя автоматически. Для бизнеса агент проверяет полноту откликов и даёт краткое сравнение по полноте и совпадению навыков. После ручного принятия предложения бизнес может фиксировать этап, фактический результат и блокер в журнале прогресса.

## Сквозная демонстрация до 5 минут

1. Откройте «Демонстрация» и нажмите «Сбросить демо».
2. Перейдите в «Конструктор задачи», загрузите слабое описание и нажмите «Проверить полноту и создать карточку».
3. Покажите минимум 3 вопроса, заполните поля карточки и зафиксируйте рост рейтинга.
4. Отметьте ручное подтверждение и опубликуйте задачу.
5. Откройте «Каталог», нажмите «Подать предложение», выберите команду и отправьте идею, план и ссылку.
6. Откройте «Отклики команд» и вручную примите или отклоните предложение.

## План реализации на 5 часов

| Время | Результат |
|---|---|
| 0–30 мин | роли, стек, схема данных и сквозной сценарий |
| 30–100 мин | ввод, вопросы AI и редактируемая карточка |
| 100–165 мин | формула рейтинга, уровни, missing fields |
| 165–225 мин | каталог, отклик, ручной выбор бизнеса |
| 225–270 мин | интеграция сценария, валидация и ошибки |
| 270–300 мин | данные, README и демонстрация |

## Тестовые сценарии

- Ввод пустого черновика: система не запускает анализ и показывает сообщение об ошибке.
- Слабое описание: AI показывает не менее трёх вопросов и не меняет факты самовольно.
- Редактирование поля: рейтинг меняется сразу, объяснение и список недостающих полей обновляются.
- Публикация без чекбокса: кнопка недоступна; после ручного подтверждения задача появляется в каталоге.
- Фильтр каталога: задачи не исчезают из системы из-за низкого рейтинга, меняется только выборка.
- Отклик: команда отправляет идею, план и ссылку; бизнес видит предложение.
- Решение: «Принять» или «Отклонить» меняет статус, автоматического назначения нет.
