# AI Sana

AI Sana — демонстрационный MVP для превращения неструктурированного описания бизнес-проблемы в проверяемую карточку задачи, публикации её в каталоге и подготовки зависимых подзадач для исполнителей.

Проект рассчитан на бизнес-заказчиков, команды исполнителей и жюри хакатона, которым нужно быстро пройти путь от идеи до понятного задания с критериями результата.

## Проблема и решение

Бизнес-задачи часто описываются слишком общо: без контекста, входных данных, пользователей, ожидаемого результата и критериев приёмки. Из-за этого исполнителю сложно оценить объём работ и предложить решение.

AI Sana помогает:

- собрать описание в единую карточку задачи;
- показать, каких сведений не хватает, и рассчитать прозрачный рейтинг полноты от 0 до 100;
- опубликовать подтверждённую карточку в общем каталоге;
- принять предложения команд вручную;
- создать зависимую подзадачу в строгом JSON-формате на основе родительской карточки.

## Что реализовано

### Конструктор бизнес-задачи

- Свободный ввод исходного описания.
- Поля компании, отрасли и контактного лица.
- Редактируемая карточка с полями:
  - контекст и потребность;
  - пользователи;
  - данные и материалы;
  - ожидаемый результат;
  - критерии успеха;
  - ограничения;
  - формат взаимодействия.
- Рейтинг полноты карточки от 0 до 100 с расшифровкой по семи показателям.
- Ручное подтверждение перед публикацией.

### AI-уточнения

При настроенном LLM API агент задаёт по одному вопросу на каждое незаполненное поле карточки. Ответы добавляются только в редактируемую карточку.

Если API недоступен или возвращает JSON не по схеме, включается локальный fallback. Он не добавляет факты от себя.

### Каталог и предложения

- Каталог опубликованных задач.
- Поиск по названию, компании, отрасли, контексту и пользователям.
- Фильтр по уровню готовности и сортировка по рейтингу или дате.
- Отправка предложения от тестовой команды с идеей, планом, сроком и необязательной ссылкой на прототип.
- Проверка минимальной полноты предложения.
- Локальные объяснимые рекомендации команд и сравнение откликов.
- Ручное принятие или отклонение предложения бизнесом.
- Фиксация фактического прогресса принятой команды.

### AI Task Agent

Агент декомпозиции получает:

- название родительской задачи;
- описание и заполненные поля родительской карточки;
- роль исполнителя;
- фокус подзадачи.

Результат проходит строгую проверку и содержит только поля:

```json
{
  "title": "",
  "goal": "",
  "input_data": "",
  "expected_artifact": "",
  "acceptance_criteria": "",
  "constraints": ""
}
```

В `acceptance_criteria` допускается не более трёх ключевых проверок. Подзадача сохраняется как черновик и не публикуется автоматически.

## Как работает решение

1. Заказчик вводит краткое описание проблемы и запускает проверку полноты.
2. Приложение создаёт черновик карточки, переносит исходные факты и рассчитывает рейтинг.
3. LLM API или локальный fallback формирует уточняющие вопросы по отсутствующим полям.
4. Заказчик отвечает на вопросы, редактирует карточку, сохраняет её и вручную подтверждает публикацию.
5. Опубликованная задача появляется в каталоге, где команда может отправить предложение.
6. Бизнес вручную сравнивает предложения, выбирает команду и при необходимости фиксирует прогресс.
7. Из карточки задачи можно открыть AI Task Agent, указать роль и фокус, получить зависимое задание и сохранить его как черновик.

## Технологии

- HTML5, CSS3, JavaScript без frontend-фреймворка.
- Python 3: локальный HTTP-сервер и API-прокси в `server.py` на стандартной библиотеке.
- Node.js 20+: альтернативный API-прокси в `server.js` на встроенном `http` и `fetch`.
- `localStorage` браузера для локального хранения задач, команд, откликов и зависимых заданий.
- OpenAI Responses API — опциональная интеграция для уточняющих вопросов и декомпозиции.
- Модель по умолчанию: `gpt-5`, задаётся через `LLM_MODEL`.
- Для OpenAI-compatible Codex endpoint предусмотрены `LLM_PROVIDER`, `LLM_BASE_URL` и `CODEX_API_KEY`/`LLM_API_KEY`.
- Для структурированного ответа используется JSON Schema / Structured Outputs.

## Архитектура проекта

```text
Браузер
  └─ index.html / app.js / styles.css
       ├─ конструктор карточки
       ├─ рейтинг и localStorage
       ├─ каталог и отклики
       └─ AI Task Agent
            ├─ POST /api/llm/clarify
            └─ POST /api/llm/decompose
                    │
                    └─ server.py или server.js
                           └─ OpenAI Responses API
```

Основные файлы:

- `index.html` — основное приложение.
- `app.js` — состояние, расчёт рейтинга, каталог, отклики, fallback и взаимодействие с API.
- `styles.css` — визуальные стили приложения.
- `server.py` — рекомендуемый локальный прокси без внешних Python-зависимостей.
- `server.js` — альтернативный прокси для Node.js.
- `demo.html` — автономная собранная версия интерфейса.
- `build-demo.cjs` — сборка `demo.html` из `index.html`, `styles.css` и `app.js`.
- `tests/app.test.cjs` — логические регрессионные тесты клиентской части.
- `DEMO.md` — сценарий презентации на пять минут.

## Установка и запуск

### Быстрый старт

Для локального запуска достаточно Python 3. Дополнительные Python-зависимости устанавливать не нужно: сервер использует только стандартную библиотеку.

1. Откройте Terminal и перейдите в папку проекта:

```sh
cd /Users/beibarys.aktileu/Downloads/hack-6fbd4f78-lem-ai-main
```

2. Запустите рекомендуемый Python-сервер:

```sh
python3 server.py
```

3. Откройте приложение в браузере:

```text
http://localhost:8000/
```

4. Чтобы остановить сервер, вернитесь в Terminal и нажмите `Ctrl+C`.

В проекте предусмотрен локальный fallback: приложение работает даже без ключа LLM API. В этом режиме вопросы и декомпозиция формируются локальной логикой приложения.

### Запуск с LLM API

LLM API нужен для генерации уточняющих вопросов и зависимых подзадач. Ключ хранится только на сервере и не помещается в клиентский JavaScript.

Если файла `.env` нет, создайте его в корне проекта:

```sh
touch .env
```

Добавьте в `.env`:

```env
LLM_PROVIDER=openai
LLM_API_KEY=ваш_ключ
LLM_MODEL=gpt-5
LLM_BASE_URL=https://api.openai.com/v1
PORT=8000
```

После этого запустите сервер из корня проекта:

```sh
python3 server.py
```

Откройте в браузере:

```text
http://localhost:8000/
```

Проверить конфигурацию прокси можно без вызова модели:

```sh
curl http://127.0.0.1:8000/api/llm/status
```

Ожидаемый формат ответа:

```json
{ "configured": true, "provider": "openai", "model": "gpt-5" }
```

Если `configured` имеет значение `false`, сервер запущен корректно, но ключ не найден. В этом случае приложение автоматически использует fallback.

### Альтернативный запуск через Node.js

Требуется Node.js 20 или новее. Перейдите в корень проекта и запустите:

```sh
cd /Users/beibarys.aktileu/Downloads/hack-6fbd4f78-lem-ai-main
node --env-file=.env server.js
```

Для совместимого Codex/OpenAI endpoint укажите `LLM_PROVIDER=codex`, `LLM_BASE_URL` и `LLM_API_KEY` или `CODEX_API_KEY`. Не запускайте одновременно два сервера на одном порту.

### Запуск без API-сервера

Для автономной демонстрации можно открыть `demo.html` двойным щелчком. В macOS это также можно сделать командой:

```sh
open demo.html
```

Либо запустите простой статический сервер:

```sh
cd /Users/beibarys.aktileu/Downloads/hack-6fbd4f78-lem-ai-main
python3 -m http.server 8000
```

Затем откройте `http://localhost:8000/demo.html`. В этом режиме доступны локальные вопросы и локальная логика, а внешние LLM-запросы недоступны.

### Первый демонстрационный сценарий

1. Откройте `http://localhost:8000/`.
2. Перейдите в раздел «Демонстрация» и нажмите «Сбросить демо».
3. Загрузите слабое описание бизнес-задачи и нажмите «Проверить полноту и создать карточку».
4. Заполните поля карточки, сохраните черновик и включите ручное подтверждение публикации.
5. Опубликуйте задачу и найдите её в каталоге.
6. Нажмите «Создать зависимое», выберите роль и фокус, затем сохраните подзадачу как черновик.
7. Переключитесь в режим студента, отправьте предложение команды, затем в режиме бизнеса примите или отклоните его.

Подробный сценарий презентации на пять минут находится в [`DEMO.md`](DEMO.md).

### Типовые проблемы

- `python3: command not found` — установите Python 3 и повторите запуск.
- `Address already in use` — порт `8000` занят. Остановите другой локальный сервер или запустите с другим портом: `PORT=8001 python3 server.py`, затем откройте `http://localhost:8001/`.
- Страница не открывается — проверьте, что сервер всё ещё работает в Terminal и что открыт именно адрес `http://localhost:8000/`.
- `configured: false` — проверьте имя файла `.env`, переменную `LLM_API_KEY` и отсутствие пробелов вокруг значения ключа. Само приложение при этом продолжит работать через fallback.
- Не запускайте одновременно `server.py`, `server.js` и `python3 -m http.server` на одном порту.

## Как проверить решение

Жюри может повторить следующий сценарий:

1. Откройте `http://localhost:8000/` и перейдите в раздел «Демонстрация».
2. Нажмите «Сбросить демо», затем загрузите слабое описание бизнес-задачи.
3. Нажмите «Проверить полноту и создать карточку».
4. Убедитесь, что появились вопросы LLM API или локального fallback, а рейтинг показывает незаполненные поля.
5. Заполните поля карточки, сохраните черновик, установите ручное подтверждение и опубликуйте задачу.
6. В каталоге найдите опубликованную задачу и нажмите «Создать зависимое».
7. Выберите роль и фокус, сгенерируйте зависимое задание и проверьте шесть JSON-полей.
8. Сохраните зависимую карточку как черновик.
9. Для проверки полного сценария переключитесь в режим студента, отправьте предложение, затем в режиме бизнеса откройте «Отклики команд» и вручную примите или отклоните его.

Для демонстрации отказоустойчивости включите переключатель «Демо: принудительно проверить fallback» перед анализом карточки.

## Данные и интеграции

- В репозитории есть встроенный тестовый набор: пять черновиков, пять команд, пять карточек задач и пять тестовых предложений.
- Пользовательские изменения сохраняются в `localStorage` браузера под ключом `ai-sana-mvp-v1`.
- Данные между браузерами и компьютерами не синхронизируются.
- OpenAI Responses API вызывается только через локальный `server.py` или `server.js`.
- Используются два endpoint прокси:
  - `POST /api/llm/clarify` — вопросы по пропущенным полям карточки;
  - `POST /api/llm/decompose` — зависимая подзадача по родительской карточке, роли и фокусу.
- `GET /api/llm/status` показывает только статус конфигурации, провайдера и модели.
- Реальные медицинские, финансовые, логистические или иные внешние системы к проекту не подключены.

## Ограничения текущей версии

- Это демонстрационный MVP, а не многопользовательская production-система.
- Нет регистрации, авторизации, ролей на сервере и общего backend-хранилища.
- Переключение «Бизнес / Студент» является демонстрационным.
- Публикация задачи и выбор команды требуют ручного действия пользователя.
- LLM API зависит от доступности ключа, биллинга, выбранной модели и сети; при ошибке используется fallback.
- API-ключ нельзя хранить в `index.html`, `app.js`, `demo.html` или отправлять в браузер.
- Локальная версия не защищает `localStorage` от доступа другим пользователем этого браузера.
- Нет реальных интеграций с CRM, календарями, мессенджерами, медицинскими системами или системами управления проектами.
- Публичная deployed-версия в текущем репозитории отсутствует.
